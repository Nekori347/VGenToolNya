# VGenToolNya — Codex 第一轮开发任务

## 0. 本轮任务定位

本轮属于 **AFK 自主开发与可体验 Demo 交付**。

不是纯调查、架构设计、静态原型，也不是等待下一轮指令才能使用的半成品。

在一次连续工作中完成：

1. 旧项目完整归档封存。
2. 两份现有 VGen 油猴脚本的功能审计和迁移。
3. VGen 真实网页、原生组件、内部状态与数据接口调查。
4. Chrome Manifest V3 扩展建立。
5. 原有功能整合与 UI 统一。
6. 本地汉化、输入框增强、AI 翻译、评价工具和订单增强的基础实现。
7. 使用真实 VGen 页面与安全模拟数据完成必要验证。
8. 交付用户可以直接安装和体验的 Demo。

**本轮不需要中途询问用户，不需要高频汇报或交接，不得在完成基础调查后自行停止等待下一轮任务。**

遇到普通技术取舍自行按本任务明确的设计约束处理。遇到无法安全验证的功能，保留实现和安全限制，并记录准确状态，不中断其他开发工作。

最终交付必须明确区分：

- 已在真实页面验证
- 已在本地模拟环境验证
- 已实现但由于账户安全限制未进行真实写入验证
- 未实现或存在阻断问题

不能把模拟功能冒充真实可用，也不能以未完成调查为理由省略整个功能模块。

## 3. VGen 真实环境调查与安全边界

用户已在以下环境登录 VGen：

- Codex 内嵌 Chrome
- 本地 Chrome

允许使用可访问的已登录环境进行只读调查。

### 3.1 严格禁止

AFK 期间不得对真实 VGen 账户执行任何主动写入行为。

禁止：

- 发送聊天消息
- 创建、修改或取消订单
- 提交评价
- 上传或发布作品
- 修改橱窗及服务
- 修改账户资料与设置
- 手动标记消息已读
- 发送表态
- 调用具有写入副作用的 VGen 接口
- 重放带认证的写入请求
- 获取、导出或泄露 Cookie、Token、会话凭据
- 把私信、委托内容或其他账户数据发送给第三方 AI API

特别注意：打开聊天会话、切换页面或加载某些组件也可能产生已读回执等副作用。

不能简单认为“没有点击保存按钮”就属于只读操作。

调查时优先观察已经加载的页面、源码和既有响应。对可能触发写入副作用的操作停止实际执行，转用源代码、模拟对象或离线测试。

调查用浏览器中不主动修改已有油猴脚本和用户配置。

### 3.2 调查深度要求

不能停留于：

- 截图
- DOM Selector
- CSS 类名
- 当前页面坐标
- 模拟输入与点击
- 单纯观察请求 URL

以前的开发已经证明，VGen 很多功能依赖 React 内部组件、回调、Redux 状态、Slate 富文本编辑器以及实际业务 API。

应调查：

1. 真实组件层级与生命周期。
2. React Fiber、Props 与原生回调。
3. Redux Store 和相关 Action。
4. Slate 等富文本编辑器状态。
5. 已发生网络请求中的真实接口、数据结构与调用关系。
6. 页面路由、Modal、Overlay、Portal 和动态挂载。
7. 原生字段实际如何接受、保存和确认状态。
8. 旧脚本已经证明有效的实现路径。

DOM 只能作为辅助证据，不能把“元素存在”当作“功能可以正常写入”。

调查应直接服务于功能实现。发现可靠依据后马上进行对应 Demo 开发，不必等到全站调查结束。

### 3.3 UI 锚点要求

过去曾出现组件定位不稳定、反复移动、重复插入以及页面重排的问题。

本项目不得无脑选择最近的 DOM 容器或写死绝对坐标。

必须判断：

- 字段实际所属业务组件
- 工具条与字段的逻辑关系
- 父容器尺寸及布局规则
- 弹窗与普通页面的区别
- 滚动与窗口缩放
- React 组件卸载和重新挂载
- 扩展自身 DOM 引起的观察器反馈

优先使用语义明确的稳定组件容器和真实布局流。

不能依赖不断重试坐标计算来维持看似正确的位置。

对已经成熟且交互合理的旧功能，优先保留其操作习惯，仅消除重复管理及不一致部分。

## 5. 新增功能一：全站本地汉化

### 核心要求

全页汉化是扩展内置本地词典功能。

**不调用 AI，不调用外部翻译服务，不对页面所有文字进行机器翻译。**

支持：

- 默认中文
- 页面按钮切换英文原文
- 设置中启用双语
- 原生 UI 文本的动态汉化
- React 重渲染后的持续正确显示
- 关闭汉化后恢复英文

覆盖画师端相关导航、菜单、表单、按钮、提示、状态、弹窗及动态加载界面。

### 必须排除

- 客户消息
- 用户输入正文
- 委托描述
- 评价正文
- 用户名
- 自定义标签内容
- 输入框当前值
- 扩展自身已翻译的内容

采用基于页面和组件上下文的词典映射，而非不加区分地全局替换英文字符串。

双语模式必须考虑 VGen 原生布局空间。不要像文章翻译扩展一样对所有文本直接插入第二行，从而导致按钮高度、弹窗位置和导航布局异常。

无法确认语义的字段保留原文，不得通过 AI 临时补译。

## 6. 新增功能二：统一输入框工具

针对实际支持的业务字段，在其下方提供常驻工具条。

例如：

`[预设] [备注] [AI 翻译]`

工具条常驻，完整编辑器默认收起。

适配范围包括：

- 作品上传标题
- 作品简介
- 作品标签
- 橱窗标签
- 聊天
- 订单相关文本
- 评价
- 其他经过调查确认适合的自定义输入字段

不是所有字段使用完全相同的工具。

例如标签选择器继续使用原生标签逻辑，不应将其强制转换成普通文本翻译框。

### 6.1 预设

- 不同业务字段有专属预设。
- 支持添加、编辑、删除及插入。
- 预设可以有名称、正文和备注。
- 旧作品上传预设能力必须保留。
- 公共预设管理集中，实际使用入口保留在对应字段。

### 6.2 AI 翻译编辑器

点击 AI 翻译后展开工具。

主要交互：

**输入原文**

感谢您的委托，我预计下周开始制作。

**英文结果**

Thank you for your commission. I expect to start working on it next week.

**中文直译对照**

感谢您的委托。我预计下周开始进行制作。

操作：

`[重新翻译] [润色] [插入] [撤回/复原]`

增加独立的 AI 备注框，用于提供意图、背景、措辞要求及纠错信息。

备注绝对不能混入最终正文。

### 6.3 翻译逻辑

中文原文 → 英文译文 → 英文独立直译回中文。

中文对照不是复制原始中文，而是针对最终英文结果重新进行直译，用于检查表达偏差。

每次重译或润色后，必须同步更新中文直译对照。

保留：

- 原文
- 当前英文与回译结果
- 上一版英文与回译结果

不需要长期保存完整翻译版本历史。

支持一步撤回及复原。

### 6.4 插入逻辑

不得边翻译边直接改写 VGen 输入框。

只有用户明确点击「插入」，才执行字段写入。

插入前保留当前字段原值，支持恢复至插入前内容。

必须通过对应字段的原生读写机制操作，并检查原生状态是否接受修改。

AFK 阶段在模拟编辑器中完整验证插入/撤回。真实 VGen 字段不得自动执行写入测试。

### 6.5 客户内容翻译

对聊天、委托需求和客户自定义内容支持按需汉化。

与全站 UI 汉化严格分离：

- 全站 UI 汉化：本地词典。
- 客户内容翻译：用户主动调用 API。

不得自动批量发送整个聊天记录或订单资料。

模型接口完成后应允许用户自行配置并使用，不得把实际可配置功能永久固定在模拟模式。

## 8. 新增功能四：评价生成器

在 VGen 原生订单完成评价区域提供 AI 评价工具。

交互：

1. 点击生成。
2. 随机生成一条评价。
3. 显示可编辑结果。
4. 可选择评价标签。
5. 点击重新生成，基于标签生成新的评价。
6. 用户确认后可以主动插入原生评价字段。

支持：

- VGen 原生可选标签
- 用户自定义标签
- 多标签组合
- 无标签随机生成
- 自定义语气和内容预设

不自动提交评价。

生成时应根据用户实际提供的评价意图组织措辞，不得虚构没有发生过的合作事实。

调查 VGen 真实评价组件及标签数据来源，不得仅靠界面可见文字推断字段结构。

## 9. 新增功能五：订单客户增强

### 9.1 客户名片

订单页面的甲方名片增加：

- 复制主页链接
- 复制真实用户 ID

注意区分：

- 显示名称
- 用户名或 URL Slug
- VGen 内部真实 User ID

必须通过实际数据来源确认，不允许把用户名当作真实 ID。

### 9.2 差评提醒

当真实客户评价指标不为 100% 好评时，提供明显但不干扰页面操作的提醒。

鼠标悬停显示可取得的具体差评。

必须调查：

- 好评率指标来源
- 单条评价内容
- 单条评分
- 是否存在无文字差评
- 是否存在无法访问的评价
- VGen 是否公开提供实际差评明细

不得将准时率、完成率或其他百分比误认为好评率。

若无法取得具体差评，只能展示经过确认的异常指标与明细不可用状态。

不允许伪造差评文本。

## 10. 调查与 Demo 同步推进

本轮不设置纯调查交付关卡。

正确方式：

**发现可复用实现 → 确认深层状态/接口 → 实现对应功能 → 小范围验证 → 继续下一个功能。**

优先顺序：

1. 封存旧项目并建立可加载扩展。
2. 迁移现有功能，形成统一 UI 基础。
3. 完成本地汉化与主要输入框工具。
4. 完成 API 配置及翻译编辑器。
5. 完成评价工具。
6. 完成订单客户增强。
7. 做必要的回归和真实页面体验验证。

此顺序是工作优先级，不要求所有模块完全串行。共享底座可以一次实现，不要重复搭建。

### 10.1 Demo 的真实程度

最终 Demo 必须在真实 VGen 页面中运行。

不能仅交付：

- 独立 HTML 演示
- 静态截图
- 无法交互的 UI
- 只有配置页的扩展
- 全部按钮使用同一种 Toast 占位
- 所有功能都依赖下一轮任务才能启动

功能涉及真实账户写入的部分，可使用本地模拟数据及模拟组件验证交互与完整逻辑，但不能以此替代未来真实写入验收。

**目标是功能结构与主要操作已经基本成形、用户回来主要进行体验与优化，而不是重新决定产品应该怎么做。**

### 10.2 统一视觉体验

参考旧脚本已确定的视觉设计，包括：

- 深浅主题
- 紧凑布局
- 清晰的按钮层级
- 蓝绿强调色
- 卡片与工具条风格
- 原生 VGen 页面融合

需要统一组件风格、间距和反馈，不要把不同旧脚本的两个完整管理界面并排塞进扩展。

不要大量重做视觉方案，但应解决原有 UI 整合后的明显重复与层级问题。

## 12. 最小充分验证

验证目标是交付能够让用户开始真实体验的 Demo，而不是反复证明所有实现不存在潜在问题。

至少验证：

### 扩展基础

- Chrome 能加载扩展。
- VGen 页面能够显示扩展入口。
- 不产生重复注入组件。
- SPA 路由切换和弹窗重建后不明显错位。
- 深浅主题工作正常。
- 设置可保存与恢复。

### 旧功能

按源码建立完整功能清单，逐项确认迁移状态。

对于能安全进行只读验证的内容，在真实页面检查；对有写入副作用的功能，使用本地模拟环境验证，并清楚标记。

### 本地汉化

- 默认中文。
- 可以恢复原文。
- 可以启用双语。
- 不翻译用户自定义内容。
- 不破坏主要页面布局。
- React 重渲染后能够正常工作。

### 输入框与翻译

- 工具条位置正确。
- 展开与收起正常。
- 各字段加载对应预设。
- 模拟 API 翻译结果可显示。
- 英文和中文直译对照分别显示。
- 重译、润色、撤回和复原正常。
- 模拟字段插入与恢复正常。
- AI 备注不会混入正文。

### 订单与评价

- 客户 ID、主页链接来源经过核实。
- 复制逻辑在安全环境下工作。
- 评价生成器可以通过模拟数据生成、重生成和编辑。
- 差评提醒不会把不相关指标误判为好评率。
- 缺失差评数据时不会生成虚假内容。

### 停止条件

完成必要构建、核心路径测试及与本次修改相关的回归后，停止增加重复验证。

不要反复启动新的诊断轮次，不要为了“更加确定”持续扩大测试范围。

如果一个真实接口无法安全验证，记录限制，继续其他模块。

## 15. 执行边界与自主性

**用户正在 AFK，本轮不需要中途确认。**

执行期间：

- 不需要按模块逐次交接。
- 不要把普通技术选择反复提交用户决定。
- 不要等待用户逐个授权进入下一开发步骤。
- 不要将调查报告作为最终完成标准。
- 不要因为单个未证实接口停止整个 Demo 开发。
- 不要私自扩大需求范围。
- 不要把风险性的真实账户操作当成测试手段。
- 不要在项目目录外建立临时开发项目。

允许在这些边界内完成必要实现判断。

不允许擅自改变：

- 项目形态
- 已确定的 UI 风格
- 核心功能范围
- 用户真实账户的只读安全要求
- 旧功能无损迁移目标
- 唯一工作目录要求

若某项需求无法在安全边界内完整验证，优先实现功能本身及可用的本地验证路径，保留明确的实际限制，继续完成其他工作。

**本轮的结束标准不是“调查已经充分”，而是“基础功能基本成形，Demo 能安装、能运行、能进行实际用户体验，剩余问题已经明确”。**

最终只进行一次集中交付总结，避免高频交接。
